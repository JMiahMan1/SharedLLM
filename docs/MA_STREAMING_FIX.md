# Music Assistant Streaming Architecture & Fix Plan

## Executive Summary

The current local browser music playback in Jarvis uses MA's `/preview` endpoint, which only provides ~30 second previews. To enable full-track playback, the system will use MA's official WebSocket state-sync + native `<audio src>` binding architecture (mirroring the MA web-player).

---

## Current Architecture

### Flow
```
Browser <--> Gateway (port 8000) <--> MA JSON-RPC API <--> MA /preview endpoint
```

### Implementation
- **Endpoint:** `GET /api/media/stream/music-assistant?uri=library://track/1759`
- **Handler:** `services/gateway/main.py` → `stream_music_assistant()` (lines 5022-5199)
- **Steps:**
  1. Resolve credentials from identity service
  2. Query MA JSON-RPC `music/item_by_uri` → get `provider_instance` + `provider_item_id`
  3. Proxy GET `<ma_host>/preview?provider={instance}&item_id={id}` to browser

### Problem
MA's `/preview` endpoint only provides ~30 second previews, not full tracks.

---

## Pivoted Approach: MA Official WebSocket + Native Audio Binding

### Why Not Direct Subsonic Streaming?
The original plan (documented below) was to extract OpenSubsonic provider credentials from MA and construct direct Navidrome Subsonic stream URLs. However, MA's official web-player architecture is superior:

1. **Handles all providers natively** — OpenSubsonic, local files, Spotify, Tidal, etc. without credential scraping
2. **Built-in queue management** — MA's WebSocket state sync manages player state, track transitions, seek position
3. **No credential exposure** — Gateway never needs to know provider passwords
4. **Seeking & playback control** — MA manages the stream session; browser just binds to the generated URL
5. **Official MA architecture** — This is how the MA web-player works; it's the supported approach

### MA Web-Player Architecture (Discovered via Source Analysis)

**Source:** `music-assistant/frontend/src/` components

#### Key Components Mapped
| Component | File | Purpose |
|-----------|------|---------|
| PlayerBrowserMediaControls | `layouts/default/PlayerOSD/PlayerBrowserMediaControls.vue` | **Native `<audio :src="audio">` element** — binds stream URL directly |
| WebSocket Client | `plugins/api/index.ts` | Connects to `ws://ma:8095/ws`, handles auth + command dispatch |
| Active Audio Source | `composables/activeAudioSource.ts` + `activeSource.ts` | Reactive track/state tracking |
| Player Store | `plugins/store.ts` | Reactive queue state, current track, playback state |
| Play Button | `layouts/default/PlayerOSD/PlayBtn.vue` | Sends `player/play_media` via WebSocket |

#### WebSocket Protocol
```
ws://ma-server:8095/ws
```

1. **Connection:** Browser connects to `ws://ma:8095/ws`
2. **Auth:** Sends JWT token via `auth/login` or stored token
3. **Command:** Sends `player/play_media` with `{player_id, media_type, uri}` (e.g., `library://track/1759`)
4. **State Sync:** MA broadcasts queue state updates via WebSocket containing:
   - Current track metadata
   - **Resolved stream URL** (generated by MA's stream server on port 8096)
   - Playback state (playing/paused/paused)
   - Seek position
5. **Browser:** Updates `<audio src>` with the resolved stream URL, plays via native HTML5 audio

#### Stream URL Format
MA's stream server (port 8096) generates direct audio URLs:
```
http://ma:8096/flow/{session_id}/{queue_id}/{queue_item_id}/{player_id}.mp3
http://ma:8096/single/{session_id}/{queue_id}/{queue_item_id}/{player_id}.mp3
```

These URLs are included in the WebSocket queue state updates after `player/play_media` is sent.

## MA Streaming Architecture Deep Dive (Reference)

### Music Assistant Stream Server
**Source:** `music_assistant/controllers/streams/controller.py`

MA hosts an unprotected HTTP-only webserver (default port 8096) for streaming audio packets to players.

**Routes:**
| Route | Purpose |
|-------|---------|
| `/flow/{session_id}/{queue_id}/{queue_item_id}/{player_id}.{fmt}` | Continuous flow stream (crossfade, gapless) |
| `/single/{session_id}/{queue_id}/{queue_item_id}/{player_id}.{fmt}` | Single track stream |
| `/command/{queue_id}/{command}.mp3` | Command responses (next/silence) |
| `/announcement/{player_id}.{fmt}` | Announcement audio |

**Stream URL Generation:**
```python
# From StreamsController.resolve_stream_url()
base_path = "flow" if flow_mode else "single"
return f"{self._server.base_url}/{base_path}/{session_id}/{queue_id}/{queue_item_id}/{player_id}.{fmt}"
```

These URLs require valid `session_id`, `queue_id`, `queue_item_id`, and `player_id` that are generated when media is queued for playback on a player.

### OpenSubsonic Provider
**Source:** `music_assistant/providers/opensubsonic/sonic_provider.py`

The `opensubsonic--dK3sUSj4` provider connects to Navidrome via `libopensonic` (OpenSubsonic API).

**Full Audio Streaming Flow:**
```python
async def get_audio_stream(self, streamdetails: StreamDetails, seek_position: int = 0):
    # Calls Navidrome's Subsonic API directly
    resp = await self.conn.stream(
        streamdetails.item_id,
        time_offset=seek_position,
        estimate_length=True,
        tformat=fmat
    )
    async for chunk in resp.content.iter_chunked(40960):
        yield bytes(chunk)
```

**Provider Configuration:**
- `_raw_file = True` → Original source files without transcoding
- Uses `libopensonic.AsyncConnection` for Navidrome communication
- Navidrome stream endpoint: `{baseURL}/rest/stream.song?id={songId}&u={user}&p={password}`

**Key Methods:**
- `get_stream_details(item_id)` → Returns `StreamDetails` with `item_id` (Navidrome song ID)
- `get_audio_stream(streamdetails)` → Streams audio bytes from Navidrome

## Fix Plan: Direct Subsonic Streaming

### Approach
Instead of using MA's `/preview` endpoint, query MA's config API for OpenSubsonic provider credentials and construct a direct Subsonic stream URL to Navidrome.

### New Flow
```
Browser <--> Gateway <--> MA JSON-RPC (resolve URI + get provider config) <--> Navidrome Subsonic API
```

### Implementation Steps

1. **Resolve track metadata** (same as current):
   ```python
   resp = await client.post(
       ma_api,
       json={"command": "music/item_by_uri", "args": {"uri": uri}},
       headers=auth_headers,
   )
   # Returns: provider_instance, provider_item_id, track metadata
   ```

2. **Query MA config for OpenSubsonic provider credentials:**
   ```python
   # Need to find the correct MA JSON-RPC method to get provider config
   # Likely: config/get or server/list_providers or similar
   provider_config = await ma_jsonrpc("config/get", {"key": "opensubsonic--dK3sUSj4"})
   # Returns: baseURL, username, password, port, path
   ```

3. **Construct Subsonic stream URL:**
   ```python
   # provider_item_id format: "track-{navidrome_id}"
   navidrome_id = provider_item_id.replace("track-", "")
   stream_url = f"{baseURL}/rest/stream.song?id={navidrome_id}&u={username}&p={password}"
   ```

4. **Proxy stream to browser:**
   ```python
   # Same as current implementation - proxy with range header support
   upstream = await stream_client.send(
       stream_client.build_request("GET", stream_url, headers=req_headers),
       stream=True,
   )
   return StreamingResponse(
       stream_generator(stream_client, upstream),
       ...
   )
   ```

### Required MA JSON-RPC Methods

We need to discover the correct MA JSON-RPC method to get OpenSubsonic provider config. Potential methods:
- `config/get` - Get a config value by key
- `server/list_providers` - List all providers with their configs
- `provider/get_config` - Get provider configuration
- `mass/config/get` - Get MA internal config

### Navidrome Subsonic API Details

**Stream Endpoint:**
```
GET {baseURL}/rest/stream.song?id={songId}&u={user}&p={password}&format={format}
```

**Parameters:**
- `id` / `songId` - The Navidrome song ID
- `u` - Username
- `p` - Password (or MD5 password hash for legacy auth)
- `format` - Optional: `raw`, `mp3`, `ogg`, etc. (default: use server's transcoding rules)

**Alternative Endpoints:**
- `/rest/stream.action?song={id}` - Legacy Subsonic format
- `/stream/id/{songId}` - ID3-style path (if enabled)
