# Project Status Update - 2025-12-21

## Fixed Issues

### 1. Entity Resolution Priority for Music
**Problem**: "Play music on Office TV" was selecting the Android TV device (`media_player.office_tv`) instead of the Cast device (`media_player.office_tv_chrome_2`) required for Music Assistant.
**Fix**: Updated `app/domains/media/devices.py` function `smart_resolve_entity` (specifically `_integ_priority` nested function) to prioritize Cast/MA/Sonos devices when `is_music=True`.

### 2. Redis Context Update Failure
**Problem**: After playing music via Music Assistant, the Redis context (`rag:last_media_entity:{user}`) was not being updated. This caused subsequent transport commands like "Skip" to target the wrong device (often the previous legacy device or nothing).
**Root Cause**: `redis_client` was not being passed to `MusicAssistantIntegration.play_media`.
**Fix**: 
- Modified `app/domains/media/commands.py` to explicitly pass `redis_client` to `handler.play_media`.
- Modified `app/domains/media/integrations/music_assistant.py` to add debug logging and ensure context update runs if `redis_client` is present.

## Verified Results

Verified via script `tools/verify_fix_devices.py`:
- `is_music=True` correctly prioritizes Cast devices.
- `is_video=True` correctly prioritizes AndroidTV/Roku devices.
