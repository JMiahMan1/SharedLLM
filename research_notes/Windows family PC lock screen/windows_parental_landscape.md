## Key Question 1 — Microsoft Family Safety on Windows 10/11 in detail

### Takeaway
Family Safety is a cloud-synced, per-Microsoft-child-account control plane bolted onto Windows via the Parental Controls services (`WpcMonSvc`/`WpcSvc`) and Edge. It is **Edge-and-Store-centric**, works on Home and Pro alike, and is enforced by a *child account signed in with a Microsoft account*, not by any device-owner or kernel mechanism — which is why local accounts, other browsers, admin accounts, and account-switching are all silent holes, and why lockouts and "time's up" screens are deliberately visible to the child.

### Prerequisites & mechanics
- Requires a Microsoft family group (organizer = parent, member = child) created at family.microsoft.com / account.microsoft.com/family, plus a **child Microsoft account** on the Windows device — "The child account has to be a real Microsoft child account - not a local Windows account - or the family features simply won't appear." If the child uses a **local account, none of the settings apply and Windows gives no warning** — check Settings > Accounts > Your info for "Local account". — [3Eyes Family Safety setup guide 2026](https://3eyes.app/blog/microsoft-family-safety-setup-guide-2026)
- Activity reporting needs two things: child signed into Windows 10+ with a Microsoft account **and** the organizer's Activity reporting toggle on. "The child doesn't need to be signed in to Microsoft Edge to collect browsing data." — [Microsoft Edge privacy docs](https://learn.microsoft.com/en-us/legal/microsoft-edge/privacy)
- Screen time and web filtering apply "automatically" to Microsoft Edge; "Web and search activity include websites your child visited and terms they searched for when using Bing." — [Microsoft Family Safety deck (2026)](https://cdn-dynmedia-1.microsoft.com/is/content/microsoftcorp/microsoft/msc/documents/presentations/CSR/Safe-Choices-With-Microsoft-Family-Safety.pdf)
- Screen time limits work on Windows 10/11, Xbox, and Android apps/games, managed from the mobile app or family.microsoft.com; "Mobile screen time only applies to Android." — [Set screen time limits — support.microsoft.com](https://support.microsoft.com/en-us/family-safety/set-screen-time-limits-across-devices)
- **Guest mode and InPrivate browsing aren't available if web filtering or activity reporting is turned on.** — [Microsoft Edge privacy docs](https://learn.microsoft.com/en-us/legal/microsoft-edge/privacy)
- Microsoft Store "Ask to Buy" governs purchases; Store app/game age ratings gate downloads; age-filtered apps/games for Windows and Xbox. — [Microsoft Family Safety deck (2026)](https://cdn-dynmedia-1.microsoft.com/is/content/microsoftcorp/microsoft/msc/documents/presentations/CSR/Safe-Choices-With-Microsoft-Family-Safety.pdf)
- Microsoft itself says: "Other commonly used browsers will be blocked for this to work" (i.e., Family Safety blocks Chrome/Firefox to protect the filter). — [Microsoft Family Safety download FAQ](https://www.microsoft.com/en-us/microsoft-365/family-safety-download)

### Bedtime window vs screen limits
- Per-day schedules: "Select a day to set time ranges and total hours permitted for device use" — i.e., Family Safety supports **both** a total daily allowance and allowed time-of-day ranges ("bedtime window") on the same screen; daily limit max appears to cap at ~8 hours in practice (a parent: "we have to keep resetting the time to the max, 8 hours"). — [Set screen time limits — support.microsoft.com](https://support.microsoft.com/en-us/family-safety/set-screen-time-limits-across-devices); [Microsoft Q&A, BOOM-5030, 2025-12-13](https://learn.microsoft.com/en-au/answers/questions/5659602/family-safety-problems)
- Time used is "based on how long the account is signed in, including idle time" — a child signed in but idle still burns allowance; docs say sign out, not lock, to pause accounting. — [Microsoft Q&A, 2026-03-29](https://learn.microsoft.com/en-us/answers/questions/5842262/screen-time-on-windows)
- Notifications pop up "in the final hour of his allotted time schedule" with options to request more time. — [WindowsPhoneInfo forum, 2023-11-16](https://www.windowsphoneinfo.com/threads/turn-off-screen-time-notifications-of-family-safety.1106682)

### App time limits vs Edge web filters
- **Web and search filters only work in Microsoft Edge** (and while signed into the Microsoft child account in Edge); blocked sites / "Only use allowed websites" are enforced by Edge itself. Unsupported browsers are blocked entirely "if family filtering is on; you can manually unblock a browser on the device" via App and game filters. — [Microsoft Support: Filter websites and searches](https://support.microsoft.com/en-us/family-safety/filter-websites-and-searches-using-microsoft-family-safety)
- App and game time limits (0 min → unlimited, or block) are enforced per-app by the Windows agent regardless of browser — this is the only native way to stop Chrome on a Family-Safety PC, and it's coarse (kills the whole browser, no filtering inside). — [Microsoft Q&A, 2025-12-13](https://learn.microsoft.com/en-au/answers/questions/5659602/family-safety-problems); [Microsoft Support: Filter websites and searches](https://support.microsoft.com/en-us/family-safety/filter-websites-and-searches-using-microsoft-family-safety)
- Edge web filter is category/keyword-based SafeSearch + mature-site blocking, **not a general category web filter**; Bing enforces SafeSearch keyword on results; "Other search engines may return filtered results due to the keyword." — [Microsoft Edge privacy docs](https://learn.microsoft.com/en-us/legal/microsoft-edge/privacy)
- "Filter inappropriate websites" "only enable[s] supported browser (currently Edge) to block mature content" — i.e., it's Edge-scoped, full stop, as of 2026-10 docs. — [Microsoft Support: Filter websites and searches (2026-10-15)](https://support.microsoft.com/en-us/family-safety/filter-websites-and-searches-using-microsoft-family-safety)
- Enabling Kids-Mode-style filter also disables InPrivate/Guest for the child. — [Microsoft Edge privacy docs](https://learn.microsoft.com/en-us/legal/microsoft-edge/privacy)

### Reporting & transparency
- Activity reports (Edge visits + Bing searches) available in app/web after Family Safety sync; on-device, the child sees explicit prompts — lockout screen literally shows **"Time's up"** with **"Get More Time"** button, plus **"Switch users / My parent is here / Send Request"** options at the sign-in screen. — [WindowsPhoneInfo forum: child unable to request more time, 2021](https://www.windowsphoneinfo.com/threads/family-safety-child-unable-to-request-more-time-account-locked-in-a-loop-cannot-login.585083); [WindowsPhoneInfo forum: time limit popups, 2023](https://www.windowsphoneinfo.com/threads/turn-off-screen-time-notifications-of-family-safety.1106682); [Microsoft Q&A, 2020-03-27](https://learn.microsoft.com/en-us/answers/questions/3277326/family-safety-screen-doesnt-lock-after-time-expire)
- The "ask for more time" flow is **reactive only** — child runs out, a request email goes to the parent, parent approves from app/email link (15/30/60-min style grants). There is **no built-in "pre-extend today only"** that resets automatically; parents must either approve requests or manually plan, and "Give extra time today" exists on the device screen-time section in recent builds per Microsoft staff (but parent reports vary). — [Microsoft Q&A: adding more time only today, 2025-09-17](https://learn.microsoft.com/en-us/answers/questions/5557741/adding-more-time-only-today-in-family-safety)
- Transparency is the design intent: the lockout is loud (popup in final hour, full-screen "Time's up", 15-minute-style warnings), and the child always knows they are supervised — contrast with stealth agents (Qustodio "hide" mode).

### Documented failure modes (2024–2026)
- **June 2025: Family Safety blocked Chrome en masse** on Windows — child accounts couldn't open Chrome ("unable to run when Microsoft Family Safety is enabled"); Microsoft acknowledged; expected behavior per MS (blocking non-Edge browsers is by design), but it failed closed on school Chrome use; workaround was renaming `chrome.exe` to `chrome1.exe` (unofficial, defeats the check) — some parents also got no approval prompts / approvals ignored. — [The Verge via Windows Central, 2025-06-21](https://www.windowscentral.com/software-apps/browsing/microsoft-is-blocking-google-chrome-in-the-name-of-family-safety-but-this-time-it-actually-makes-sense); [How-To Geek, 2025-07-02](https://www.howtogeek.com/microsoft-family-safety-feature-is-blocking-chrome-on-windows)
- **December 2025: widespread Family Safety web-filter/policy sync outage** — filtering silently stopped across Edge for many users (worked for 5 months, then stopped); Microsoft Q&A threads flooded; Reddit/homeschool reports; support tier 2 acknowledged and even reject escalation; resets/re-adds gave ~15–20 h of function then failed again — assessed as server-side/policy-sync issue. — [Microsoft Q&A, 2025-12-17](https://learn.microsoft.com/en-us/answers/questions/5667309/microsoft-family-safety-filtering-is-not-working-f); [Microsoft Q&A, 2025-12-19](https://learn.microsoft.com/en-us/answers/questions/5671004/family-safety-not-working)
- **Screen-time reporting silently dies when services stop** — `WpcMonSvc` (Parental Controls) / `WpcSvc` stopped and wouldn't restart → no usage shown, app limits unenforced ("12 hours a day playing Roblox"). Fix often = set child to **Admin temporarily**, let Family Safety re-attach, set back to Standard — against all Microsoft guidance. — [Microsoft Q&A, 2025-06-01](https://learn.microsoft.com/en-us/answers/questions/3864263/my-son-is-bypassing-family-safety-limits); [Microsoft Q&A, 2025-10-28 / 2026-01-10](https://learn.microsoft.com/en-us/answers/questions/5601117/family-safety-not-reporting-screen-time)
- **Sync/time-zone/parental-consent glitches**: time limit "worked for 14h, then unlimited" after reinstall; device on for 6 h with 15-min limit shows "you will be locked out at 9:56 PM"; parents must clear ProgramData\Microsoft\Windows\Parental Controls and force re-sync. — [Microsoft Q&A, 2025-08-06](https://learn.microsoft.com/en-us/answers/questions/5515352/microsoft-family-screen-time); [Microsoft Q&A, 2025-06-28](https://learn.microsoft.com/en-au/answers/questions/2288093/why-is-microsoft-family-not-limiting-my-childs-scr)
- **Settings don't apply / "Unable to connect to Microsoft Family Safety"** in Settings > Family — TPM resets, local↔MS account switching, re-adds — persistent dead-ends reported through 2025–2026. — [Microsoft Community Hub, 2025-04-28](https://techcommunity.microsoft.com/discussions/windows11/unable-to-connect-to-microsoft-family-safety/4408677)
- **Approvals lost / requests never arrive**: "Get More Time" sends nothing; family-wide lockout loops at sign-in ("Time's up" + no other user on device + request never reaches parent). — [WindowsPhoneInfo forum, 2021](https://www.windowsphoneinfo.com/threads/family-safety-child-unable-to-request-more-time-account-locked-in-a-loop-cannot-login.585083); [Get More Time notifications broken, 2023](https://www.windowsphoneinfo.com/threads/turn-off-screen-time-notifications-of-family-safety.1106682)
- **Location/driving-safety features are being removed** from Family Safety (2026 notice) — shrinking scope. — [Microsoft Family Safety download page](https://www.microsoft.com/en-us/microsoft-365/family-safety-download)
- **The "everything else" hole**: settings only apply to the MS child account — other (local, unlisted) accounts on the same device are unmanaged with no warning; a child signing out of Edge drops the filter for that session; changing time zone/clock skews enforcement; apps limits don't cover all launch paths (e.g., Store vs desktop apps vs web wrappers). — [3Eyes Family Safety setup guide 2026](https://3eyes.app/blog/microsoft-family-safety-setup-guide-2026); [Microsoft Q&A, 2025-12-17 (VPN uninstall non-fix)](https://learn.microsoft.com/en-us/answers/questions/5667309/microsoft-family-safety-filtering-is-not-working-f)
- **Windows 10 EOL (14 Oct 2025)** — Family Safety on Win10 is now living on borrowed time (ESU only). — [Microsoft Windows 10 compare page](https://www.microsoft.com/de-de/windows/compare-windows-11-home-vs-pro-versions); [Windows 11 lifecycle](https://learn.microsoft.com/ms-my/lifecycle/products/windows-11-home-and-pro)

### Home vs Pro & edition limits
- Family Safety works on **Windows 10/11 Home and Pro** — Microsoft lists "Kindersicherung und Schutz" (child safety/screen time) as a shared Windows feature; no edition gate in docs. What editions gate is everything *else*: gpedit.msc and Assigned Access require Pro+; Shell Launcher requires Enterprise/Education; WCF/ZTDNS require Enterprise/Education; gpedit is absent on Home (registry HKLM\SOFTWARE\Policies still works on Home — it's just keys). — [Windows 11 Home vs Pro compare — Microsoft](https://www.microsoft.com/de-de/windows/compare-windows-11-home-vs-pro-versions); [Windows 11 editions comparison — Group Policy is Pro-only](https://yourwindowsguide.com/2025/06/windows-11-home-vs-pro-versions.html); [Geek Rewind Chrome Secure DNS (GP needs Pro; registry works on Home)](https://geekrewind.com/how-to-enable-secure-dns-in-google-chrome/)
- On **Home**, Microsoft's own parenting story is: MS child account + Edge filter + Store limits. That is the *entire* native surface. Anything stronger (Assigned Access, AppLocker, GPO, ZTDNS) is Pro/Enterprise-only — a deliberate channel split.
- **WpcMonSvc/Parental Controls** exist on both editions but their health is not surfaced to the parent (services can be Stopped with no UI warning) — the most dangerous silent failure in the product. — [Microsoft Q&A, 2025-06-01](https://learn.microsoft.com/en-us/answers/questions/3864263/my-son-is-bypassing-family-safety-limits)

### What it silently can't control
- Non-Edge browsers (blocked wholesale by design — not filtered), VPN apps/tunnels (no VPN filter), local child accounts (invisible), admin child accounts (self-disarming), unsigned-in Windows state (Edge filter follows Edge sign-in), other users on the same PC, time-zone/clock manipulation [attempted, partially mitigated by server sync — [UNCERTAIN]], **non-Edge HTTPS** (nothing inspects it), LAN/proxy/Tor (not handled). — [Microsoft Support: Filter websites and searches](https://support.microsoft.com/en-us/family-safety/filter-websites-and-searches-using-microsoft-family-safety); [3Eyes setup guide 2026](https://3eyes.app/blog/microsoft-family-safety-setup-guide-2026); [Microsoft Q&A, 2025-12-17](https://learn.microsoft.com/en-us/answers/questions/5667309/microsoft-family-safety-filtering-is-not-working-f)
- Bedtime doesn't stop a *logged-in* child from keeping a web wrapper app open; enforcement happens at sign-in/session and app-launch events, not as an in-session hard kill in all cases — reports of "laptop does not always lock itself" on expiry, especially with UWP apps like Minecraft running. — [Microsoft Q&A, 2020-03-27](https://learn.microsoft.com/en-us/answers/questions/3277326/family-safety-screen-doesnt-lock-after-time-expire) [older; behavior in 2026 [UNCERTAIN]]

### Inferences
- Family Safety is fundamentally **account-bound, not device-bound**: security boundary = "child MS account + Edge + Store". Any design review of a self-hosted agent should treat "per-account, per-browser, cloud-sync policy" as a ceiling, not a floor.
- The loud, honest lock screen ("Time's up", "Get More Time", "My parent is here") is the *correct* transparency pattern — it matches the parent-developer's goal of signage over stealth. Its failure mode is sync, not honesty.
- The Dec 2025 outage proves the control plane is fragile and server-mediated; a self-hosted agent should fail locally and observably, not degrade silently.

### Gaps
- Exact on-device enforcement internals (service timers, AppX hooks) not documented by Microsoft publicly.
- Whether bedtime "time ranges" survive DST/clock changes cleanly in 2026 — no current source found.
- Whether "Give extra time today" launched broadly vs. app regression — sources conflict (staff answer vs. parent reports of missing option).
- Whether Family Safety lock screen text differs between Home and Pro — not documented.

## Key Question 2 — ChromeOS/Assigned Access comparison ("device owner" model)

### Takeaway
ChromeOS has a cryptographic **device-owner** model: the first user (or enrolling organization) owns the device, signs device settings with an owner private key, and enterprise ownership can be established at OOBE only on an ownerless device — users can't self-promote, and ownership resets require factory reset. Windows has **no equivalent**; its closest analogues are admin rights and kiosk policy (Assigned Access), both weaker and edition-gated. This owner model is why Family Link supervision on Chromebooks is dramatically harder to shed than Family Safety on Windows.

### Cited findings
- Consumer ChromeOS: "The first user created on the device becomes the owner"; ChromeOS generates an owner key pair; device settings are "signed by the private part of the owner key"; all users can verify with the public key; owner key can be regenerated only if device settings claim current user is owner. — [Chromium source: components/ownership](https://chromium.googlesource.com/chromium/src/+/46fa99d0f2b3c1a940c25e4849a3fbeff2be0a6a/components/ownership)
- Enterprise: enrollment establishes org ownership "only on devices without owner" — i.e., OOBE-time decision; ownership reset requires factory reset (Ctrl+Alt+Shift+R) unless disabled by policy; "Only enterprise users can enroll devices." — [Chromium source: docs/enterprise/enrollment.md](https://chromium.googlesource.com/chromium/src/+/fde062ce944c6238d9217cfd2109242f1ffad73f/docs/enterprise/enrollment.md)
- Family Link supervises Chromebooks (ChromeOS 71+): parents manage app blocks, screen-time limits, Chrome website filtering, extensions — full device-level supervision once signed into a child Google Account; supervised accounts restrict evasive sign-ins. — [Google Family Link FAQ](https://families.google/familylink/faq/); [Google For Families: Chrome & child accounts](https://support.google.com/families/answer/7087030?hl=en)
- Windows has no owner-key model: any local admin can alter policies; edition gates hide the strong tools behind Pro/Enterprise (see KQs 3 & 6); the Family Safety boundary is a *session+cloud* boundary, not a hardware/cryptographic one. — [Assigned Access overview: edition list](https://learn.microsoft.com/en-us/windows/configuration/assigned-access/overview); [Family Safety docs](https://support.microsoft.com/en-us/family-safety/set-screen-time-limits-across-devices)

### Inferences
- The Windows design gap for a self-hosted agent: you cannot revoke admin-from-the-child the way ChromeOS revokes owner-ness. The agent must therefore (a) make the child a standard user, (b) deny policy-write access via HKLM ACLs/WDAC/AppLocker, (c) rely on a separate parent-controlled PIN or parent account for anything sensitive — mimicking "owner vs user" in software.
- Signage parity: ChromeOS shows "managed by your organization" prominently; a family agent should adopt the same plain-labeled transparency rather than hide.

### Gaps
- Exact Family Link ChromeOS enrollment UX 2026 (screenshot-level) not needed for design; not researched.
- Whether Windows 11 has any hidden "device owner" notion for consumer — none found in any Microsoft source; treated as absent, not literally disproven.

## Key Question 3 — Assigned Access (kiosk) on Pro/Enterprise: what it could contribute, and why parental suites don't use it

### Takeaway
Assigned Access is Microsoft's only built-in "standard child runs a restricted shell" primitive: multi-app kiosk = standard desktop + Start menu limited to allowed apps + AppLocker + lockdown policies, on **Pro/Enterprise/Education/IoT only (not Home)**, configured per-account via XML/CSP/GPO. It is the strongest *native* answer to app budgets on a family PC, but it's designed for fixed-purpose shared devices (frontline/lab/signage), assumes a single use-case, and demands console sign-in + UAC — so it fits a family PC as a "school hours mode" far better than as an always-on bedtime enforcer, and no consumer parental suite ships it.

### Mechanics & requirements
- Assigned Access supports **kiosk (single-app, UWP or Edge, full-screen above lock screen, auto-restart)** and **restricted user experience (multi-app kiosk)**: defined app list + tailored Start/Taskbar + enforced policy settings and **AppLocker rules**, works for standard/domain/Entra accounts. — [Assigned Access overview](https://learn.microsoft.com/en-us/windows/configuration/assigned-access/overview)
- **Editions: Pro, Enterprise/Enterprise LTSC, Education, IoT Enterprise only — Home is not supported.** Shell Launcher (replace explorer.exe with a custom app) is **Enterprise/Education only**, not Pro. Kiosk + Assigned Access can't coexist with Shell Launcher on one system. — [Assigned Access overview](https://learn.microsoft.com/en-us/windows/configuration/assigned-access/overview); [Kiosk configuration options overview](https://learn.microsoft.com/en-us/windows/configuration/kiosk/)
- Requirements: UAC enabled; console sign-in only (RDP unsupported); policy applies on next sign-in; some lockdown policies apply to standard users only, some also to admins. — [Configure single-app kiosk](https://learn.microsoft.com/en-us/windows/configuration/assigned-access/configure-single-app-kiosk); [Assigned Access overview](https://learn.microsoft.com/en-us/windows/configuration/assigned-access/overview)
- Configuration paths: Settings UI (single local account), PowerShell (Set-AssignedAccess), CSP/MDM (Intune), PPKG, **GPO** — XML configuration file specifying apps (desktop app AUMID/path) and the account. — [Multi-app kiosk — PowerShell tab](https://learn.microsoft.com/en-us/windows/configuration/assigned-access/configure-multi-app-kiosk?tabs=ps); [Assigned Access Configuration Designer reference](https://learn.microsoft.com/en-us/windows/configuration/wcd/wcd-assignedaccess)
- Kiosk mode auto-applies "a set of policy settings… to optimize the lock-down experience"; Shell Launcher has no default lockdown policies, just swaps explorer.exe. — [Kiosk configuration options overview](https://learn.microsoft.com/en-us/windows/configuration/kiosk/)
- Edge kiosk mode exists (full-screen Edge kiosk with optional branded profile) usable as the multi-app/single-app vehicle. — [Kiosk configuration options overview](https://learn.microsoft.com/en-us/windows/configuration/kiosk/)
- Registry/GPO mechanics: Assigned Access config is stored via CSP/MDM (AssignedAccess CSP) — under the hood it lands as policy in the **HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\AssignedAccess** area and applies per-user via profile XML (not a documented public key schema; verify on-device) [UNCERTAIN — not documented on a single stable doc page]. AppLocker rules live under **HKLM\SOFTWARE\Policies\Microsoft\Windows\SrpV2\**. Browser policies (see KQ5) live under HKLM\SOFTWARE\Policies\…. Direct HKLM policy keys work on Home even without gpedit; the Assigned Access feature itself does not. — [Assigned Access CSP/PowerShell doc](https://learn.microsoft.com/en-us/windows/configuration/assigned-access/configure-single-app-kiosk); [WCD reference](https://learn.microsoft.com/en-us/windows/configuration/wcd/wcd-assignedaccess); [Geek Rewind (GP=Pro-only, registry works on Home)](https://geekrewind.com/how-to-enable-secure-dns-in-google-chrome/)
- Removal: clear config via PowerShell/WMI bridge (`$obj.Configuration = $null`) + reboot; note "can't revert all changes. For example, in a multi-app kiosk scenario the Start menu configuration is maintained." — [Single-app kiosk removal](https://learn.microsoft.com/en-us/windows/configuration/assigned-access/configure-single-app-kiosk)

### What it could contribute to a family PC
- **Bedtime/school "focus mode" as a standard-user profile on a Pro family PC**: e.g., child's account runs Assigned Access multi-app with Edge-en-only-school-sites + Word + a homework app during school hours; outside hours the policy simply isn't applied (or a different config swaps in). Stronger than app-name blocking because **AppLocker deny-blocks unlisted executables at the SRP layer**.
- **App budgets with teeth**: combine multi-app allowed list (allowlist model — far stronger than blocklist) with a watcher process that toggles the AA config by time-of-day.
- **Kiosk "sign-out screen" substitution** for bedtime: swap in/out an AllowedTimeout or Edge-kiosk-lock screen rather than overlay windows.
- Microsoft Edge **Web Content Filtering** also exists but needs M365 licensing & the Edge management service — not for home, and it also blocks *other browsers* as a side effect. — [Configure WCF on Edge](https://learn.microsoft.com/en-us/deployedge/microsoft-edge-web-content-filtering); [WebContentFilteringBlockedCategories policy](https://learn.microsoft.com/en-us/deployedge/microsoft-edge-policies/webcontentfilteringblockedcategories)

### Why parental suites mostly don't use it [inference, flagged]
- Edition gate (Home excluded) kills the consumer TAM — the same reason market suites rely on services + overlay + browser hooks instead.
- Single-use design: no per-account "sometimes restricted, sometimes not" time-of-day logic built in — you must build a config-swapper (MDM/PowerShell/WMI), which is exactly the self-hosted agent the parent-developer is building.
- Friction: console-only sign-in, reboot/sign-out to switch modes, Start menu persistence on removal, unsupported on RDP (breaks remote parent admin).
- Support cost: enterprise feature, no MS Store/consumer support path; parental vendors would inherit enterprise-grade edge cases (AppLocker SRP quirks, LOB app exceptions).
- It doesn't do web content (only apps/shell) — suites already need a web layer, so AA adds a second mechanism, not a replacement.

### Inferences
- AA is the best lever for a *"school hours allowlist"* and the worst lever for *"bedtime overlay with one-minute warning"*. Use it for app budgets (mode: school), not as the primary bedtime UX; for bedtime, a full-screen overlay + forced lock (see KQ4) matches child-facing expectations better.
- A parent-developer on Pro can ship AA-based "school mode" as an opt-in; on Home the same outcome needs WDAC/AppLocker-via-registry + service overlay (Pro-less AppLocker SRP via registry keys is possible to set but unenforced without policy service configuration — [UNCERTAIN]; AppLocker service needs Pro/Enterprise for policy enforcement).

### Gaps
- Exact on-disk registry keys for the Assigned Access profile (CSP-mapped, not public) and whether Home can enforce AppLocker via registry alone — not found; flagged uncertain.
- No public source states commercial parental suites considered and rejected AA; the "why suites don't use it" list is inference from requirements/editions, not a quote.

## Key Question 4 — Third-party suites: architecture and failure patterns

### Takeaway
All major suites converge on the same architecture: a **privileged Windows service + a per-user agent/overlay that counts active time and shows warnings + browser-level enforcement (extension, policy, or web-proxy/VPN) + cloud rule sync**, with tamper detection as a paid differentiator. Their universal weaknesses on family PCs: standard-user-only assumptions break under admin child accounts, clock/time-zone changes defeat time accounting, VPNs and unrecognized browsers defeat web filtering, and "ask-for-time" flows are approval-latency-bound — which is exactly where a transparent local agent can win.

### Qustodio
- Windows agent runs a service (process `qengine`); child sees/hidable; install asks whether to hide; stealth mode redirects blocked pages to Google search instead of a block screen. It can block/launch-control browsers it knows (Brave, Tor blocked from launching in PCMag's test) but treats unknown browsers as unmanaged. — [VPN Central: Qustodio Windows internals & qengine](https://vpncentral.com/can-vpn-bypass-qustodio/); [PCMag UK Qustodio review 2022](https://uk.pcmag.com/parental-control-monitoring/38338/qustodio)
- Filtering = "DNS level on some platforms and through browser extensions on others"; blocked-site page on Windows; monitors even incognito; cross-browser (Chrome/Firefox/Edge on Windows). — [Security.org Qustodio review 2026-01](https://www.security.org/parental-controls/qustodio/)
- VPN bypass is a documented gap: kids using VPN apps it doesn't recognize evade filtering; web filtering "disappeared while using a VPN" (PCMag test). — [PCMag UK 2022](https://uk.pcmag.com/parental-control-monitoring/38338/qustodio); [XNSPY community breakdown 2026-05](https://community.xnspy.com/t/qustodio-vs-norton-family-which-is-the-best-choice/668); [Does Qustodio block VPNs — Acciyo Nov 2026](https://www.acciyo.com/does-qustodio-block-vpns-unpacking-the-tech-how-to-handle-it)
- Clock manipulation defeats time-based rules (reads device clock) — Anchor (a competitor) calls this "documented… across Android parental control forums"; parent reviews echo. — [GetAnchor Qustodio comparison 2026-05](https://www.getanchor.store/qustodio-vs-anchor)

## Key Question 5 — Browser-level policy blocking: Edge/Chrome URLBlocklist & policy schema

### Takeaway
Browser enterprise policies are the one browser-block lever that is **machine-enforced, elevation-required-to-change, and HKLM-based — viable on Home**, applied to every user including standard child accounts. Effective pattern: HKLM\SOFTWARE\Policies\Microsoft\Edge\URLBlocklist and HKLM\SOFTWARE\Policies\Google\Chrome\URLBlocklist (REG_SZ list, numbered 1..N, cap ~1000 entries), plus ForceBingSafeSearch/ForceGoogleSafeSearch (integer/bool) — with the nasty surprise that **value 0 for ForceBingSafeSearch means "no restrictions"**, and bare "Security-ish" policies with empty/unset values give no protection at all. Policies work on Home because they're just registry keys; only the *editing UI* (gpedit) needs Pro.

### Edge policies
- `URLBlocklist` (≥ Edge 77): HKLM\SOFTWARE\Policies\Microsoft\Edge\URLBlocklist, REG_SZ list 1,2,3…; max 1000 entries; `*` = block all; scheme optional; "doesn't prevent the page from updating dynamically through JavaScript"; blocking internal pages not recommended; dynamic refresh yes; **does not apply to profiles signed in with a Microsoft account? No wait — it applies to MS-account-signed-in profiles too = Yes** [per doc: "Applies to a profile that is signed in with a Microsoft account: No" for URLBlocklist — see below]. — [Edge URLBlocklist policy](https://learn.microsoft.com/en-us/deployEdge/microsoft-edge-policies/urlblocklist)
  - Note: `URLBlocklist` "Applies to a profile that is signed in with a Microsoft account: **No**" — meaning MS-profile-signed-in Edger 77+ may treat it differently [UNCERTAIN practical impact; standard family child accounts sign in to Windows, not necessarily to Edge — Edge filter follows Windows child sign-in for Family Safety, but policy is per machine].
  - `URLAllowlist` takes precedence over blocklist. — same doc
  - Edge **category** blocking `WebContentFilteringBlockedCategories` exists but is **M365-licensed, edge-management-service only, Windows Edge only** — not available for home self-host; also blocks *other browsers* as side effect. — [WebContentFilteringBlockedCategories](https://learn.microsoft.com/en-us/deployedge/microsoft-edge-policies/webcontentfilteringblockedcategories); [Configure WCF on Edge](https://learn.microsoft.com/en-us/deployedge/microsoft-edge-web-content-filtering)
  - Edge feature `WebContentFilteringBlockedCategories` GP path Administrative Templates\Microsoft Edge, ADMX MSEdge.admx. — same doc
- `ForceBingSafeSearch` (integer, REG_DWORD, HKLM\SOFTWARE\Policies\Microsoft\Edge): **0 = BingSafeSearchNoRestrictionsMode ("Don't configure search restrictions"), 1 = Moderate (filters images/videos only, not text), 2 = Strict (text+images+videos)**. "If you disable this policy or don't configure it, SafeSearch… isn't enforced." **Moderate does NOT filter text results** — the most surprising gap for parents. Dynamic refresh; applies to MS-account-signed-in profiles. Example registry value 0x00000000 shipped labeled "Don't configure search restrictions in Bing." — [Edge ForceBingSafeSearch policy](https://learn.microsoft.com/en-us/deployedge/microsoft-edge-browser-policies/forcebingsafesearch)
  - Surprise variant: the user-facing "Your country or region requires a strict Bing SafeSearch setting" message is a **Bing-side region/network lock, not a local policy** — deleting local Edge policy registry keys does not remove it (observed Aug 2026 WinUtil issue). — [ChrisTitusTech/winutil #5024](https://github.com/ChrisTitusTech/winutil/issues/5024)
- `ForceGoogleSafeSearch` (bool): enabled ⇒ Google SafeSearch always active; disabled/unset ⇒ not enforced. Same MS-account-applies-yes. — [Edge ForceGoogleSafeSearch](https://learn.microsoft.com/en-us/deployedge/microsoft-edge-policies/forcegooglesafesearch)
- `ForceYouTubeRestrict` exists similarly (strict/moderate) [Interfaces docs mention; not fetched — [UNCERTAIN detail]]
- `DnsOverHttpsMode` ("off"/"automatic"/"secure") and `DnsOverHttpsTemplates`: unconfigured managed devices get **no DoH sent**; "automatic" tries DoH then falls back to insecure; setting enforceable by HKLM policy REG_SZ — see KQ6. — [Edge DnsOverHttpsMode](https://learn.microsoft.com/en-us/deployedge/microsoft-edge-policies/dnsoverhttpsmode); [DnsOverHttpsTemplates](https://learn.microsoft.com/en-us/deployedge/microsoft-edge-policies/DnsOverHttpsTemplates)

### Chrome policies
- `URLBlocklist`/`URLAllowlist` via **HKLM\SOFTWARE\Policies\Google\Chrome** (GP path Administrative Templates\Google\Google Chrome; or direct registry on Home); list cap **1000 URLs** (Blocklist scanned per navigation — Chromium design doc); allowlist precedence; `*` host = all hostnames; filter format `[scheme://][.]host[:port][/path][@query]`; scheme `*` allowed as `*.*` / `scheme:*`; `chrome://` not recommended; verify at `chrome://policy`; requires restart; Linux config dir or registry on Windows; needs managed/GPO (not just user settings) to be non-overridable. — [Chrome: Allow or block websites — Chrome Enterprise Help](https://support.google.com/chrome/a/answer/7532419); [Chromium policy design doc](https://chromium.googlesource.com/chromium/src/+/b84cb1ef04a5c/docs/enterprise/policy_design.md); [URL blocklist format](https://support.google.com/chrome/a/answer/9942583?hl=en)
- Standard child account: policies are machine/user-hive HKLM → **not changeable by a standard user**; only an admin can clear them. Editing UI (gpedit) requires Pro, but **HKLM registry deployment works on Home**. — [Geek Rewind: Secure DNS (GP needs Pro; Registry method works without Pro)](https://geekrewind.com/how-to-enable-secure-dns-in-google-chrome/)
- Firefox equivalent: `policies.json` / GPO `WebsiteFilter` — arrays `Block`/`Exceptions` with match patterns (`<all_urls>`, `https://*/*`); Windows registry path `Software\Policies\Mozilla\Firefox\WebsiteFilter\Block\1`. Note: **the "WebsiteFilterList" name in the brief is Firefox's policy family ("WebsiteFilter"), not Edge/Chrome** — Edge/Chrome use URLBlocklist-style keys. — [Firefox WebsiteFilter policy reference](https://firefox-admin-docs.mozilla.org/reference/policies/websitefilter)
- Verify enforcement: edge://policy, chrome://policy (click Reload; look for Status=OK). — [Chrome enterprise help](https://support.google.com/chrome/a/answer/7532419)
- "Security: default behavior with empty SafeSearch": with nothing configured (or value 0 for Bing / false for Google/YouTube), **no SafeSearch is enforced — user choice rules**; with Moderate, text isn't filtered; the only fully-closed states are Bing=2 / YouTube=Strict / Google=true. In other words, a naively "half-configured" family-safety registry looks protective and is **not**. — [ForceBingSafeSearch](https://learn.microsoft.com/en-us/deployedge/microsoft-edge-browser-policies/forcebingsafesearch); [ForceGoogleSafeSearch](https://learn.microsoft.com/en-us/deployedge/microsoft-edge-policies/forcegooglesafesearch)

### Cross-browser reality check
- Browser policies are **per-browser**: Chrome discipline doesn't cover Firefox/Brave/Edge-SW-mode; a self-hosted agent still needs browser-enumeration + install-blocking (HKLM policies or AppLocker) to make "the one browser" story stick — exactly the hole Family Safety has and third-party suites both plug (launch-block) and leak (unknown VPN/browser).
- Policies do **not** stop DoH in the browser itself unless you also set DnsOverHttpsMode=off (or a specific template), or Network Protection/ZTDNS blocks DoH endpoints — see KQ6.
- URLBlocklist is bypassable by JavaScript-driven single-page navigation to blocked paths [per doc limitation], and it doesn't see inside HTTPS SNI-less routing — policy ≠ proxy.

### Inferences
- For a self-hosted agent targeting standard-user children on **Home**: ship **registry policies for Edge+Chrome+Firefox (ForceSafeSearch=Strict/true, YouTube=Strict, URLBlocklist, DoH off-or-pinned) plus an AppInstall/launch watcher** — all local, reversible by admin, zero licensing cost. This is a *strictly stronger* baseline than Family Safety's "Edge only or nothing".
- Pre-seed `chrome://policy`-style verification into the parent dashboard (agent writes keys, then reads edge://policy via CLI or registry ack) — visibility of "is the policy actually live" is a trust feature nobody ships today.

### Gaps
- Exact behavior of Edge URLBlocklist against Microsoft-account-profile Edge instances on Home (the "Applies to MS-account profile: No" flag) — doc states it, real-world impact untested; flagged [UNCERTAIN].
- YouTube restriction enum values (Strict/Moderate/Unset) not directly verified from docs here — believed same 0/1/2 pattern; verify on-device.
- Policy key for blocking extension *installation* (`ExtensionInstallBlocklist`) and `DefaultSearchProvider*` not researched in depth.

## Key Question 6 — Windows 11 24H2/25H2, Edge DoH & Chrome Secure DNS defaults (2025–2026)

### Takeaway
Encrypted DNS silently defeats DNS-based filters by default: **Chrome auto-upgrades to DoH when the system resolver supports it ("use secure DNS" on by default)**, and **Edge defaults to "Automatic" secure DNS backed by Windows 10/11's DoH support + hardcoded provider mappings** — meaning household DNS filters (and self-hosted Pi-hole-style category filters) are bypassed *by the browsers in 2026, by default, silently*. Enterprise counterparts (Edge policy `DnsOverHttpsMode=off`, Chrome policy `SecureDnsMode`, or ZTDNS on Enterprise/Education) exist but are admin-gated and license-gated — Home users get no native DoH off-switch except toggling the browser UI (child can't) or policy keys (parent can set).

### Edge / Windows 11 DoH
- Edge "Use secure DNS" defaults to **current-provider mode; if the current DNS server is DoH-capable, Edge upgrades silently** (WebNots walkthrough 2025-05; Edge blog 2020: "By default, Edge uses your current secure DNS provider"). Set per-OS in Windows 11 network settings → DNS → "On (automatic template)". — [WebNots Edge Secure-DNS walkthrough](https://www.webnots.com/what-is-secure-dns-and-how-to-use-it-in-microsoft-edge); [Windows 11 Forum: Secure DNS default = current provider](https://www.elevenforum.com/t/enable-or-disable-secure-dns-over-https-in-microsoft-edge.12470)
- Windows 11 DNS client supports **DoH with known-server list** and per-interface "On (automatic template)"/"Encrypted only"/"Encrypted preferred"; `netsh`/Settings toggle; NRPT policy exists via GPO for Pro/Enterprises; **Windows Server 2022+ has NRPT DoH (`Allow DoH`/`Prohibit DoH`/`Require DoH`)** — Allow/Prohibit/Require is the enterprise switch a family agent can emulate via registry. — [Windows Server DoH client docs](https://learn.microsoft.com/en-us/windows-server/networking/dns/doh-client-support?tabs=powershell); [Zero-Trust DNS deploying](https://learn.microsoft.com/en-us/windows/security/operating-system-security/network-security/zero-trust-dns/deploying-zero-trust-dns)
- **Edge enterprise policy `DnsOverHttpsMode`: off/automatic/secure; automatic = DoH first w/ insecure fallback; secure = DoH only**; if policy unconfigured on managed devices → no DoH sent; `DnsOverHttpsTemplates` hardcodes resolver; insecure fallback is the filter-killer. Registry: HKLM\SOFTWARE\Policies\Microsoft\Edge\DnsOverHttpsMode = REG_SZ. — [Edge DnsOverHttpsMode](https://learn.microsoft.com/en-us/deployedge/microsoft-edge-policies/dnsoverhttpsmode); [DnsOverHttpsTemplates](https://learn.microsoft.com/en-us/deployedge/microsoft-edge-policies/DnsOverHttpsTemplates)
- Windows 11 **Zero Trust DNS (ZTDNS)** — announced Build-era 2025-11 (Win11 Enterprise/Education, admin, DoH/DoT-only, WFP default-deny outbound): Microsoft's explicit answer to "DoH defeats filters", but **not available to Home/Pro consumers** — a signal of platform direction. — [Tech Community blog 2025-11-18](https://techcommunity.microsoft.com/blog/networkingblog/zero-trust-dns-is-here-elevating-enterprise-security-on-windows-11/4468743); [Deploying ZTDNS](https://learn.microsoft.com/en-us/windows/security/operating-system-security/network-security/zero-trust-dns/deploying-zero-trust-dns)
- Windows Server "DoH on server side" shipped June 2026 (KB5094125, 2026-06) — irrelevant to households but shows Microsoft is fully committed to DoH as default rail. — [Microsoft Learn: DoH server](https://learn.microsoft.com/en-us/windows-server/networking/dns/dns-encryption-dns-over-https)

### Chrome Secure DNS
- Chrome: **"Use secure DNS" is ON by default** — "By default, Chrome will automatically upgrade you to DNS-over-HTTPS if your current service provider supports it. You can also configure a different secure DNS provider in the Advanced security section, or disable the feature altogether." — [Google blog 2020-05-19](https://blog.google/products-and-platforms/products/chrome/more-intuitive-privacy-and-security-controls-chrome/); still on by default per 2025 support docs ("enabled by default on most web browsers" — Barracuda) — [Barracuda CloudGen Access: How to disable Secure DNS](https://documentation.campus.barracuda.com/wiki/spaces/BCGA/pages/1769628/How+to+Disable+Secure+DNS)
- Chrome's internal async resolver **ignores the OS DoH** — Chrome uses its own resolver; configurable via policy (`SecureDnsMode`-family; docs mention policy as override; OS-level DoH ignored in Chrome per Chromium bug 337445645 (Apr 2024) — "Forces" internal resolver, removed async resolver opt-out Feb 2024). — [Chromium bug 337445645](https://issues.chromium.org/issues/337445645)
- Autoupgrade mappings: Chrome upgrades known ISP resolvers to their DoH counterparts via built-in provider list; users on unknown ISPs may silently stay plaintext (good for filters) or silently encrypt (bad) — nobody can predict. — [Chromium docs: adding DoH providers](https://chromium.googlesource.com/chromium/src.git/+/refs/heads/main/net/docs/adding_doh_providers.md)
- Chrome Secure DNS policy: `SecureDnsMode` (off/automatic/secure) — the enterprise knob Thompson referenced; set via masterprefs/policy. [Named in Red Sift guide as "HttpsOnlyMode / SecureDnsMode policy posture"] — [Red Sift Oct 2025](https://redsift.com/guides/google-https-guide); [Geek Rewind](https://geekrewind.com/how-to-enable-secure-dns-in-google-chrome/)
- 2025–2026 adjacent defaults shift: **HTTPS-first by default from Chrome 154 (Oct 2026)** and Enhanced Safe Browsing users in Chrome 147 (Apr 2026) — not a DNS change but lowers HTTP-filter visibility further. — [Google blog "HTTPS by default" 2025-10-28](https://blog.google/security/https-by-defau)
- Reddit r/privacy flagged exactly what this means for DIY filters: default Secure DNS "bypasses everything" vs self-hosted DNS. — [r/privacy 2025](https://www.reddit.com/r/privacy/comments/1kqxczd/fyi_the_default_dns_setting_in_chrome_will_bypass)

### Windows 11 24H2/25H2 context
- Lifecycle: 24H2 ends 14 Oct 2026; 25H2 (9/30/2025) ends 13 Oct 2027; Win10 EOL 14 Oct 2025. Home SKUs ship 24H2/25H2 with DoH known-servers enabled out of the box — the platform actively pushes encrypted DNS, hostile to classic DNS filters. — [Windows 11 lifecycle](https://learn.microsoft.com/ms-my/lifecycle/products/windows-11-home-and-pro); [Windows compare](https://www.microsoft.com/de-de/windows/compare-windows-11-home-vs-pro-versions)
- Edge DoH "Automatic" + Chrome "use secure DNS" on + Firefox DoH rollout (US/Canada since 2020) = **all three major engines encrypt DNS by default in 2026**; a family filter's DNS layer must either be the system DoH resolver itself, use SNI/HTTPS-layer inspection (EDR-style), or accept blindness.

### Inferences
- A self-hosted Windows family agent must **ship policy to pin `DnsOverHttpsMode=off` (Edge) + `SecureDnsMode=off` (Chrome) + Firefox `network.trr.mode=5` / enterprise policy, or ship DoH on its own port via Wi-Fi/router** — otherwise all its DNS-based category filtering is ornamental.
- Alternatively design around DoH: inspect via WFP callouts (what ZTDNS does) — heavy; or proxy with CA injection — breaks on HSTS/eFused sites and is ethically fine for kids but operationally fragile; same trade-off every commercial filter faces.
- "Automatic" for Edge on Windows = unpredictable per-network; the parent-developer should default-pin "off" + their own filtered DoH template, i.e., inverted but honest (filter-in-DoH is one upstream hop away from transparency).

### Gaps
- Firefox 2026 default DoH status in more locales beyond 2020 US/CA rollout — not re-verified here.
- Exact Chrome `SecureDnsMode` registry value type (REG_SZ string "off|automatic|secure") — documented generally, not fetched key-by-key; flag [UNCERTAIN].
- Whether Edge "automatic" on Home-family Win11 networks actually triggers autoupgrade for common consumer ISPs — provider-list-dependent, unverifiable locally.

## Key Question 7 — Market/design lessons: why vendors fail on family PCs, and what transparent signage earns

### Takeaway
Commercial parental products were architected for managed enterprise fleets (admin-owned, Pro/Enterprise, GPO/MDM) and retrofitted onto consumer Home PCs with standard users, uneven sync, and no real enforcement layer — so they fail predictably on Home: silent services stall (WpcMonSvc), DoH bypasses their DNS filters, and admin children uninstall them. Their shared UX weakness is approval latency and opaque enforcement. **Transparent, loud, well-designed signage ("Time's up / Get More Time / My parent is here") costs nothing technically, creates genuine cooperation, and is the one thing a self-hosted, parent-developer agent can ship as a first-class feature** — alongside local fail-closed enforcement, which neither Microsoft nor vendors guarantee.

### Why enterprise-grade vendors fail at family PCs (Home)
- Edition wall: every strong lever (AppLocker, AA, GPO, WDAC, ZTDNS, WCF category filter, EDR network protection) is **Pro/Enterprise/Education-gated and license-gated**; Home gets service+cloud+overlay only. — [Assigned Access editions](https://learn.microsoft.com/en-us/windows/configuration/assigned-access/overview); [WCF licensing](https://learn.microsoft.com/en-us/deployedge/microsoft-edge-policies/webcontentfilteringblockedcategories); [ZTDNS requirements](https://learn.microsoft.com/en-us/windows/security/operating-system-security/network-security/zero-trust-dns/deploying-zero-trust-dns)
- Home = consumer MS accounts: child logged into Windows with a *standard* MS child account is fine, but one flip to local/admin silently un-governs everything with no warning (documented across Family Safety support threads; true for suites too — Safe Mode/admin uninstall). — [3Eyes](https://3eyes.app/blog/microsoft-family-safety-setup-guide-2026); [Microsoft Q&A 2025-12](https://learn.microsoft.com/en-us/answers/questions/5667309/microsoft-family-safety-filtering-is-not-working-f); [GetAnchor](https://www.getanchor.store/qustodio-vs-anchor)
- Cloud-sync dependence: Family Safety's Dec-2025 mass outage (filtering dead for days/weeks, MS support escalation rejected) — a family product must enforce **locally and observably**, or it's an honor system with telemetry. — [Microsoft Q&A 2025-12-17](https://learn.microsoft.com/en-us/answers/questions/5667309/microsoft-family-safety-filtering-is-not-working-f)
- DoH-by-default browsers neutralize DNS filtering silently — vendors didn't adapt fast enough (Net Nanny flagged vulnerable to "DoH DNS switching"). — [parentalcontrolreview matrix](https://parentalcontrolreview.com/matrix/bypass-vulnerabilities); [r/privacy 2025](https://www.reddit.com/r/privacy/comments/1kqxczd/fyi_the_default_dns_setting_in_chrome_will_bypass)
- Approval UX is terrible across the board (email round-trip; "no Give extra time for today" absent; wrong-surface requests) — kids experience friction as arbitrary tyranny, triggering workarounds (account-switching, renaming chrome.exe, VPNs). — [Microsoft Q&A 2025-09-17](https://learn.microsoft.com/en-us/answers/questions/5557741/adding-more-time-only-today-in-family-safety); [How-To Geek 2025-07-02](https://www.howtogeek.com/microsoft-family-safety-feature-is-blocking-chrome-on-windows)
- Wrong incentive design: suites hide themselves (Qustodio "hide" mode) → child discovers deception → trust collapses → circumvention becomes a game. Transparency is cheaper. — [VPN Central](https://vpncentral.com/can-vpn-bypass-qustodio/)

### What transparent signage earns (brief)
- Family Safety's own enforcement is *loud*: final-hour popups, "Time's up" screen, "Get More Time" button, "My parent is here" override — parents reviewing it repeatedly rate the **UX as understandable even when the sync fails**. Moral: kids forgive rules they can see; they fight rules that feel invisible. — [windowsphoneinfo 2021/2023](https://www.windowsphoneinfo.com/threads/family-safety-child-unable-to-request-more-time-account-locked-in-a-loop-cannot-login.585083); [Microsoft Q&A 2025-06](https://learn.microsoft.com/en-us/answers/questions/3864263/my-son-is-bypassing-family-safety-limits)
- Norton's 5-minute-every-5-minutes warning cadence from T-15 min is a good template for a "one-minute warning" design. — [Norton support v127151815](https://support.norton.com/sp/en/us/norton-snap/1.0/solutions/v127151815)
- Kaspersky's Restricted app budgets + warn-vs-block choice = direct model for "ask-for-time flow" with child agency. — [AV-Comparatives 2025](https://av-comparatives.org/tests/parental-control-review-kaspersky-safe-kids-for-windows); [SafetyDetectives](https://www.safetydetectives.com/best-parental-control/kaspersky-safe-kids)
- Trust earned: visible agent + "here's your day" counter reduces the adversarial loop that drives VPN/DoH/renaming workarounds — an open, signed, local agent can literally show its config and log (verifiable transparency), which *no* commercial suite offers.

### Design lessons for the parent-developer's agent (synthesis)
1. **Fail closed locally**: enforcement in a local service/watchdog with local policy cache — cloud sync is advisory only. (Fixes Dec-2025-class outages.)
2. **Enforce at the strongest layer available per edition**: Pro → Assigned Access/AppLocker for app budgets + HKLM browser policies; Home → HKLM browser policies + service watchdog + overlay-as-lock — be explicit about per-edition capability in docs.
3. **Standard-user-only contract + tamper telemetry** (clock skew, WpcMonSvc death, policy-key overwrite, Safe Mode flag) with parent alert — like Qustodio's "tampering detected" but with a continuous re-check loop.
4. **DoH is not optional**: pin browser DoH off (Ecco—policy keys), run filtered DNS (or same-DoH resolver) as the web-category engine, and treat VPN-app install as a policy event.
5. **Copy the good UX**: labeled lock screen, "ask for more time" with parent one-tap grant (and *today-only* semantics), 5/15/1-min warnings, visible daily budget counter — transparency as the enforcement multiplier.
6. **No stealth mode** — publish the agent's presence; sign the binary; let kids read the local log with parent.
7. **App budgets at launch-time + SRP**, not just counting minutes — minutes are cheap to fake; blocked executables aren't.
8. **One-minute warning + overlay = lock screen**, not topmost window; combine with forced sign-out or "My parent is here" PIN unlock.
9. **Home ≠ Pro honesty**: ship different capability matrices; don't promise ZTDNS-class guarantees on Home.
10. **Observability for the parent**: local event log of policy reads/writes, edge://policy-style self-check, weekly diff email — the auditability Microsoft and suites don't give parents.
